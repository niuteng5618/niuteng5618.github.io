推理流程

**prompt**:输入的一段文本

**tokenization**:将文本进行tokenization,切分为单词或字符，形成token序列。

序列化-> 

['BOS','君','不','见','黄','河','之','水','天','上','来','，' ,'奔','流','到'...'与','尔','同','销','万','古','愁','EOS']



假设语料库索引化->

['BOS','10','3','67','89','21','45','55','61','4','324','565' ,'789','6567','786'...'7869','9','3452','563','56','66','77','EOS']

**embedding**：文本经过tokenization后变为了token序列，embedding将每个token映射为实数向量，名为embedding vector

'BOS'-> [p_{00},p_{01},p_{02},...,p_{0d-1}]

'10' -> [p_{10},p_{11},p_{12},...,p_{1d-1}]

'3'  -> [p_{20},p_{21},p_{22},...,p_{2d-1}]

...

'EOS'-> [p_{n0},p_{n1},p_{n2},...,p_{nd-1}]

**<font style="color:#191B1F;">位置编码</font>**<font style="color:#191B1F;">：对于Token序列中的每个位置，添加位置编码（Positional Encoding）向量，以提供关于Token在序列中位置的信息。位置编码是为了区分不同位置的Token，并为模型提供上下文关系的信息。</font>

**<font style="color:#191B1F;">自回归生成</font>**<font style="color:#191B1F;">：在生成任务中，使用自回归（Autoregressive）方式，即逐个生成输出序列中的每个Token。在解码过程中，每次生成一个Token时，使用前面已生成的内容作为上下文，来帮助预测下一个Token。</font><font style="color:#F33232;">很多模型都是自回归模型</font>

**RMSNorm**

<font style="color:#000000;">LLama模型首先经过embedding层，然后依次经过32个transformer。</font>

<font style="color:#000000;">其中，LLama的transformer没有使用LayerNorm(标准的transformer)进行tensor的归一化，而是RMSNorm。</font>

[<font style="color:#003884;">RMSNorm</font>](https://link.zhihu.com/?target=https%3A//arxiv.org/pdf/1910.07467.pdf)<font style="color:#191B1F;">是LayerNorm的变体，RMSNorm省去了求均值的过程,也没有了偏置β，</font>

RMSNorm在分子上移除了均值项，这点在论文里面有实验解释re-center的操作没有很重要

RMSNorm仅使用平方根的均值，与使用方差相比，可以<font style="background-color:yellow;">降低噪声的影响</font>

（个人认为最重要的）简化了LayerNorm, 相比较以前均值和方差的计算量，现在只需要计算RMS, 大大<font style="background-color:yellow;">减少了计算时间</font><font style="color:#18191c;background-color:yellow;">（7%-64%）</font><font style="color:#18191C;">作为开源模型，使用者没有那么强的算力，因此减少cost能为开源项目带来更多的优势</font>

**<font style="color:#000000;">KV cache</font>**

<font style="color:#000000;">假设“</font><font style="color:#191B1F;">将进酒：人生得” 来预测下一个"意"字，所以需要把</font>**<font style="color:#191B1F;">"将进酒：人生得"</font>**<font style="color:#191B1F;">进行token化后再进行Attention计算，如下图。</font>

![](/images/yuque/004-llama/image-17-f123bfca.png)

<font style="color:#000000;">但是，其实</font><font style="color:#191B1F;">已经把</font>**<font style="color:#191B1F;">"将进酒：人生"</font>**<font style="color:#191B1F;">所对应的Q,K,V进行过相关的运算，所以没必要在对他们进行Attention计算。</font>

<font style="color:#191B1F;">KV Cache便是来解决这个问题的：通过将每次计算的K和V缓存下来，之后新的序列进来时只需要从KV Cache中读取之前的KV值即可，就不需要再去重复计算之前的KV了。</font>

<font style="color:#191B1F;">对于Q，也不需要将所有Q都计算，只计算最新的Q_newtoken即可。如下图。只计算Q_newtoken与 K_newtoken 的乘积(Q_oldtoken计算完就不要了，K_oldtokens和V_oldtokens缓存起来)。</font>

![](/images/yuque/004-llama/image-18-6f14ccbe.png)

<font style="color:#191B1F;">然后将结果与 V_newtoken 进行乘积。</font>

![](/images/yuque/004-llama/image-19-0b5f61f7.png)

<font style="color:#535861;">解释1：至于为什么不用缓存Q？ 我理解这是一种</font><font style="color:#F33232;">单向注意力机制</font><font style="color:#535861;">，他只管每次进来的token与past tokens的注意力，而past tokens不会管后面token的注意力，所以就不需要Q_past_tokens,也就不需要缓存Q</font>

<font style="color:#535861;">解释2：Q表示当前步查询的词向量，K、V表示之前生成的词的表示。K类似储存了哪些信息，Q在K中进行相似度匹配，随后与V加权生成关注程度。从这个角度理解的话，Q是需要每一步都要动态计算的，无法缓存。因此可以进行kvcache，每一步只计算Q_newtoken。</font>

<font style="color:#535861;">解释3：</font>这是因为Q通常只涉及当前时间步的数据，因此无需缓存。而K和V代表了上下文信息，它们在未来的每一个时间步都可能被用来与新的Q进行匹配。缓存K和V允许模型在处理长序列时避免重复计算，提升推理效率。

**<font style="color:#191B1F;">为什么可以进行cache，从GPU结构角度理解。</font>**

<font style="color:#191B1F;">越靠近GPU的ALU(逻辑运算单元)，速度越快</font>

<font style="color:#191B1F;">越远离ALU，内存越大</font>

<font style="color:#191B1F;">一般(SRAM)只有几十M的大小，7B的模型处理4096序列长度就需要512M的缓存空间了，更何况130B，所以cache一般存储在global memory(显存)中。</font>

<font style="color:#191B1F;">但是显存有一个明显的缺点，运算慢，这会导致一个问题</font>**<font style="color:#191B1F;">Memory wall(内存墙)。</font>**<font style="color:#191B1F;">简单来说就是处理器ALU太快，单内存读写速度慢跟不上，导致ALU算完在那等着你把数据读进来，影响性能。</font>

![](/images/yuque/004-llama/image-20-dcd9104a.png)

**<font style="color:#191B1F;">解决Memory Wall</font>**<font style="color:#191B1F;">(内存墙)的方法：</font>

**<font style="color:#191B1F;">硬件层面，</font>**<font style="color:#191B1F;">使用</font>**<font style="color:#191B1F;">高速带宽内容(HBM)</font>**<font style="color:#191B1F;">来提高读取速度，或者抛弃冯诺依曼架构，改变计算单元从内存读数据的方式，不再以计算单元为中心，而是以存储为中心，做成计算和存储一体化的"存内计算"，比如 </font>**<font style="color:#191B1F;">忆阻器</font>**<font style="color:#191B1F;">。</font>

**<font style="color:#191B1F;">软件层面，</font>**<font style="color:#191B1F;">引入</font>**<font style="color:#191B1F;">优化算法</font>**<font style="color:#191B1F;">，例如</font>**<font style="color:#191B1F;">GQA</font>**<font style="color:#191B1F;">。</font>

总结来说，RoPE 的 self-attention 操作的流程是：对于 token 序列中的每个词嵌入向量，首先计算其对应的 query 和 key 向量，然后对每个 token 位置都计算对应的旋转位置编码。

接着对每个 token 位置的 query 和 key 向量的元素按照 **两两一组** 应用旋转变换（见上面一个公式），最后再计算 query 和 key 之间的内积得到 self-attention 的计算结果（用qk变换后的结果计算内积）。
